## Findings

### What worked well

- **What happened**: Release preflight check 2 (clean worktree) caught an untracked `docs/solutions/workflow-issues/squash-merge-commit-message-not-rewritten.md` before any release source collection began, forcing a commit-first-then-retry path that kept the release range clean.
  **Why**: The preflight reads `git status --porcelain` and rejects any dirty state; the untracked file would have been invisible to the release range but represented uncommitted session work.
  **How to apply**: Commit or discard all pending work before invoking release; the preflight is the safety net, not the workflow.
  **Cites**: Phase 2 session data
- **What happened**: Four-way agreement (manifests, CHANGELOG heading, commit subject, tag) verified on first attempt with no mismatch, across a 37-commit release range covering 6 specs.
  **Why**: The release ceremony's single fail-fast bash program writes all four surfaces atomically; divergence is impossible when the program runs without error.
  **How to apply**: Maintain the single-script release program; manual edits to any of the four surfaces outside the program are the primary divergence risk.
  **Cites**: Phase 2 session data

### Process observations

- **What happened**: The retro draft initially classified carry-forward item 2 as "Not started — trigger has not fired" when in fact two shipping-gate commits (9e4ebd3 F17, f2efda9 F18) landed between retros. The facilitator's warrant check caught the false measurement before the doc was committed.
  **Why**: The respondent checked only whether this session changed shipping gates, not whether any commit since the previous retro (2026-08-16) did. Event-based carry-forward triggers fire on any qualifying commit in the inter-retro window, not only commits from the current session.
  **How to apply**: When reconciling event-based carry-forward items, query the full inter-retro commit range (`git log <prev-retro-date>..HEAD -- <trigger-path>`), not the current session's commits alone.
  **Cites**: T1, T2
- **What happened**: PRs #17 (F17 gate) and #18 (payload slimming) merged after the 2026-08-16 retro with no retrospective run. The W2 misclassification was a symptom; skipped retros are the root cause — the retro skill's own entry trigger is "a merged PR," and two qualifying merges passed without firing it.
  **Why**: No automated trigger invokes the retro skill after a PR merge; it relies on the user or orchestrator to invoke it. Between 2026-08-16 and 2026-08-22, the `docs/retros/` directory received no new entries while two PRs merged.
  **How to apply**: After each PR merge, either invoke the retro skill or explicitly defer with a stated reason; a missing retro compounds carry-forward reconciliation drift across cycles.
  **Cites**: T4; `docs/retros/` listing; PR #17 (9e4ebd3), PR #18 (792f0ec)
- **What happened**: v0.11.0 release commit (7d65dbb) and annotated tag are local-only; `git ls-remote --tags origin` shows no v0.11.0. This is by-design — the release skill's gated publication requires a separate `publish` invocation — but the session ended with a pending publish-or-hold decision unrecorded.
  **Why**: The release skill explicitly does not push; publication is a distinct ceremony. The session completed the local release but did not record the deferred publication decision.
  **How to apply**: Record the publish-or-hold decision as part of the release report when the session ends without publishing.
  **Cites**: T4; `git ls-remote --tags origin`; release skill handoff rule

## Lessons

- A carry-forward trigger keyed to "next change to X" fires on any qualifying commit in the inter-retro window, not only the current session's work — reconciliation must query the full range.
- Skipped retros compound carry-forward drift: two PR merges without retros let the W2 misclassification accumulate silently.
